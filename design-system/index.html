Neon Collection Design System

The complete token set, four character themes and every UI component behind the Durex × Star Wars — Neon Collection site, documented for rebuilding in Figma. Values are reconciled straight from style.css and quiz.css; the machine-readable set lives in design-system/tokens.json (Tokens Studio format).

Colour

The site commits to one world: near-black ground, four saturated neon accents that carry all meaning and glow. Neutrals carry a blue-violet bias (never pure grey). Only one neon is “active” at a time — exposed to components as --theme-neon / --accent.

Character themes

Each character retints the whole UI by swapping two variables — --theme-neon and --theme-neon-dim (the neon at 15% alpha) — plus a matching glow. In Figma model these as a mode set (“Stormtrooper / Grogu / Mace Windu / Darth Vader”) on one collection, so a single component instance can be recoloured by mode.

Radius & border

Radius grows with the element’s footprint: 4–8px for controls, 10–16px for cards and sections, pill/round (30–40px) for toggles and the HUD, full circle for dots. Border widths: 1px hairline, 1.5px default (selected states, quiz), 2px emphasis (banners, game viewport).

Elevation & glow

There are no soft grey drop-shadows for depth — elevation reads through neon glow. Every glow is built from the active accent (frequently via color-mix() or an hsla dim). Negative spread (-4px/-6px) keeps the bloom tight around the element.

Motion

Four named transitions. Interactive feedback is fast; spatial changes use the custom “normal” ease; meters and bars fill slowly. Card flip has its own curve. All decorative animation must yield to prefers-reduced-motion.

fast0.2s ease — button/switch hover, colour-btn, pay-method
normal0.4s cubic-bezier(.25,.8,.25,1) — cards, nav dots, glow fades, image zoom
slow0.8s cubic-bezier(.25,1,.5,1) — progress bar & stat-fill grow
flip0.7s cubic-bezier(.4,.2,.2,1) — character card rotateY(180deg) on hover

Export to Figma

Two complementary paths — do both for a full rebuild. The tokens file gives you Figma Variables; the plugin import gives you a frame of every component you can turn into Figma components.

A · Variables — via Tokens Studio

Install the plugin

In Figma: Plugins → Tokens Studio for Figma (free community plugin).

Load the token set

Plugin menu → Tools → Load from file/folder (or paste JSON) and select design-system/tokens.json from the project. You’ll get sets: global, components, and one per character under themes/.

Enable sets & export

Turn on global + components as “Source”, activate one themes/* set, then Export → Create/Update Figma variables. Repeat per character, or map the four themes/* sets to four modes in one variable collection.

Wire text & effect styles

Use the plugin’s style generation for typography (the 9-step scale in §Typography) and for the neon boxShadow/text-glow tokens in §Elevation, so they land as reusable Figma effect & text styles.

B · Components — via html.to.design

Install the plugin

Figma community plugin html.to.design. It imports a live URL or pasted HTML as editable Figma layers (auto-layout, real text, styles).

Import this page

Run the plugin → Import from URL and paste the published address of this design-system page (or use “Import code” with this file’s HTML). Set width ≈ 1280 and import with fonts enabled — Orbitron & Space Grotesk are Google Fonts, so they resolve.

Also import the live site

Import http://localhost:8000 section by section for real imagery/spacing in context; combine with the clean component frames from this page.

Componentise & bind

Select each demo block → Create component; add variants for the states shown (rest / hover / selected / disabled, and the 4 themes). Bind fills/strokes/effects to the variables from path A so a mode switch recolours everything.
